# 源代码静态审计平台（Source Code Security Audit Console）

一个**零第三方依赖**的网页版源代码安全审计工具。读取指定文件夹内的代码，执行静态扫描，
按风险等级分级展示结果，提供文件/行号定位与修复建议，并内置**第三方依赖漏洞扫描（SCA）**——
解析 30 种依赖清单、对接 OSV.dev 漏洞库，按严重程度列出受影响依赖与修复升级建议；
每次审计独立建档（**项目隔离**），支持一键导出审计报告（**Word / docx**、HTML、Markdown、CSV、JSON 五种格式）。

## 一、快速开始

### 方式 1：双击启动（Windows）

```
双击 audit-tool/start.bat
```

> Linux / macOS 使用 `bash audit-tool/start.sh`（效果等同）。
>
> 启动器会自动探测本机 Python 解释器；若本机装了多个版本或安装在非常规位置，
> 可显式指定：`set AUDIT_PYTHON=D:\Python313\python.exe`（Linux/macOS 用
> `export AUDIT_PYTHON=/usr/bin/python3`）后再次双击。

### 便携迁移：拷到其他电脑直接用

本工具**零第三方依赖、全部路径相对化**，整个 `audit-tool/` 目录（U 盘 / 压缩包）
拷贝到任何一台装有 **Python 3.9+** 的电脑上即可运行，无需安装、无需配置、不改注册表：

1. **先在目标机器上自检**（可选但推荐）：双击 `checkenv.bat`，或在命令行执行
   `python app.py --check-env`。它会一次性核对 Python 版本、目录可写性、端口占用、
   联网与漏洞库缓存，并明确告诉你「环境就绪，可直接运行」还是缺什么；
2. 拷贝 `audit-tool/` 整个目录（或直接使用发行包 `audit-tool-portable-*.zip`）；
3. 双击 `start.bat`（Windows）或运行 `bash start.sh`（Linux/macOS）；
4. 首次运行会自动创建 `reports/`、`workspaces/` 等运行时目录，`projects/` 中的
   历史项目档案与 `vulndb/cache.json` 漏洞库缓存随包携带、离线可用。

> ⚠️ 目标目录需**可写**：请避免把工具放在 `C:\Program Files` 等受保护位置，
> 否则报告与归档无法落盘（`--check-env` 会直接指出这一点）。

自检亦自包含：解压到全新目录后运行 `python selftest.py`，当工具父目录不含可审计
内容时会自动回退到随包分发的 `selffixture/` 夹具目录完成全部断言
（夹具为刻意构造的漏洞演示代码，请勿在生产代码中参考其写法）。

### 依赖项与环境要求

| 项目 | 要求 | 说明 |
| :--- | :--- | :--- |
| 操作系统 | Windows 7 SP1+ / 主流 Linux / macOS 10.13+ | 纯标准库，无 C 扩展、无原生依赖，架构无关 |
| Python 运行时 | **3.9 或更高**（推荐 3.10 – 3.13） | **唯一**的必需依赖；Windows 安装时建议勾选 `Add Python to PATH` |
| 第三方包 | **无** | 无需且不应执行 `pip install`；请勿创建虚拟环境来装依赖 |
| 磁盘空间 | 约 30 MB + 运行数据 | 运行数据含报告、上传工作区（最多 6 份）、项目档案、漏洞库缓存 |
| 目录权限 | 工具目录可写 | 用于写入 `reports/`、`workspaces/`、`projects/`、`vulndb/` |
| 网络（可选） | 可访问 `osv.dev` | 仅「在线依赖漏洞库（SCA）」需要；无网时自动降级为只读本地缓存，静态扫描不受影响 |
| tkinter（可选） | 由 Python 自带 | 仅用于「系统原生对话框」快捷方式；缺失时自动隐藏，改用内置网页目录浏览器，功能等价 |
| 浏览器 | Chrome / Edge / Firefox / Safari 近三年版本 | 需支持 ES2020；「浏览器原生目录选择器」仅在 `http://127.0.0.1` 或 `https` 等安全上下文可用 |
| 端口 | 默认 `8770`（仅监听 `127.0.0.1`） | 被占用时自动顺延到下一个空闲端口，无需干预 |

**一键核对**：`python app.py --check-env`（或双击 `checkenv.bat`）会把上表逐项实测一遍并给出结论。
标准库中用到版本相关特性的地方（如 `tomllib`）均已做降级处理，因此 3.9 与 3.13 行为一致。

### 方式 2：命令行

```bash
cd audit-tool
python app.py --root "C:/Users/wk/Desktop/源代码审计" --port 8770
```

启动后浏览器访问 **http://127.0.0.1:8770/**。首次使用：

1. 点击顶栏中间的 **「审计目标」** 胶囊 → 选择「从浏览器选择」并挑选代码目录（或改用「服务器目录」）；
2. 选好后点击右上角 **「开始扫描」**（弹窗里也可直接选「选择并扫描」一步到位）；
3. 扫描完成后在中间栏看源码、右侧看结果，右上角「导出报告 ▾」导出 Word/HTML/CSV 等。

| 参数 | 说明 | 默认值 |
| :--- | :--- | :--- |
| `--root` | 启动时预置的待审计目录（之后可在界面随时改） | 本工具的上一级目录 |
| `--port` | 服务端口 | `8770` |
| `--host` | 监听地址 | `127.0.0.1` |
| `--open` | 启动后自动打开浏览器 | 关闭 |
| `--no-reuse` | 端口被占用时不复用、直接报错 | 关闭 |
| `--strict-port` | 端口被占用时直接报错（顺延端口的反向） | 关闭 |
| `--no-vulndb` | 关闭依赖漏洞分析（只做静态扫描与依赖清单） | 关闭 |
| `--offline` | 漏洞库离线模式：只读本地缓存，不发起网络请求 | 关闭 |
| `--vulndb-ttl` | 包级漏洞查询缓存时长（小时） | `24` |
| `--check-env` | 只做运行环境自检后退出，不启动服务（别名 `--doctor`） | 关闭 |

> 端口已被本平台占用时，启动器会**复用**已有实例并打印其地址；
> 若占用者是其他程序，会自动顺延到下一个空闲端口。
>
> 运行要求：Python 3.9+。**不需要** pip install 任何东西。
> 详见上文「依赖项与环境要求」，可用 `--check-env` 一键核对。
>
> 💡 「服务器目录」的**网页目录浏览器**由本工具自己列举服务器文件系统（纯标准库），
> **不依赖 tkinter**，任何 Python 3.9+ 环境都能正常选目录；
> 「系统原生对话框」为可选快捷方式，仅在解释器自带 tkinter 时显示。

## 二、技术方案

### 2.1 总体架构

```
audit-tool/
├── app.py                  HTTP 服务与 REST API（gzip / 缓存 / 分组查询 / 上传工作区 / 扫描线程 / 漏洞分析线程 / 项目隔离 / 环境自检）
├── core/
│   ├── meta.py             **元信息单一真源**：工具名 / 版本号 / 反馈邮箱 / 最低 Python 版本
│   ├── rules.py            规则库（48 条规则 / 10 大类 + 冲突处理策略，纯声明式配置）
│   ├── engine.py           扫描引擎：遍历 → 语言识别 → 匹配 → 降噪 → 冲突合并 → 评级
│   ├── textio.py           文本读取与换行归一的单一来源（行号一致性保证）
│   ├── manifests.py        依赖清单解析（30 种文件名模式，Maven 父 POM/属性两阶段合并）
│   ├── projects.py         审计项目隔离：唯一 ID / 快照落盘 / 列表与删除
│   ├── vulndb.py           OSV.dev 客户端：批量查询 / 并发详情 / 区间匹配 / 修复推导 / 别名去重
│   ├── cvss.py             CVSS v3.1 / v2.0 基础分自算（FIRST 规范，纯标准库）
│   ├── docx.py             零依赖 DOCX（OOXML）生成器 —— 手写 XML + zipfile
│   └── reporter.py         报告导出（DOCX / HTML / JSON / Markdown / CSV）
├── web/                    前端（原生 HTML + CSS + JS，无构建步骤）
│   ├── index.html
│   ├── style.css
│   └── app.js
├── samples/                自检样例（故意含漏洞的代码，用于验证规则）
├── projects/               **审计项目档案**：每次扫描一个 `<项目ID>/` 子目录，
│                           内含 project.json（元数据）与 result.json（完整快照），互不干扰
├── reports/                导出的报告存放目录（可在界面「报告历史」中查看）
├── vulndb/                 漏洞库磁盘缓存（包级 24h / 公告详情 7d 两级 TTL，自动淘汰）
├── workspaces/             上传模式的工作区副本（自动只保留最近 6 份）
├── selftest.py             端到端自检脚本（155–156 项断言，需先启动服务）
├── vulntest.py             SCA 核心离线测试（79 项断言，Mock OSV 响应，无需服务与网络）
├── manifesttest.py         依赖清单解析离线测试（24 项断言，运行时生成夹具，无需服务与网络）
├── ruletest.py             离线自检脚本（规则夹具 + 行号不变量，无需服务）
├── start.bat / stop.bat    Windows 一键启动 / 停止
├── checkenv.bat            Windows 一键环境自检（等价于 app.py --check-env）
├── start.sh                Linux / macOS 启动器（--check-env 亦可）
└── README.md
```

### 2.2 技术选型与理由

| 层 | 技术 | 选择理由 |
| :--- | :--- | :--- |
| 服务端 | Python 3.9+ **标准库**（`http.server` / `re` / `json` / `csv` / `gzip` / `zipfile`） | 零依赖 = 换任何机器都能直接跑，不受网络与内网 pip 源限制，便于在隔离的审计环境中部署 |
| 扫描内核 | 自研 **正则 + 上下文守护** 规则引擎 | 无需编译、无需构建索引，可扫描任意语言混合的代码库；规则以纯数据形式声明，运维/安全人员可直接增删 |
| Word 导出 | **手写 OOXML + zipfile**（`core/docx.py`） | 不引入 python-docx / lxml，保持零依赖；支持标题层级、表格、代码块底纹、条形图、页眉页脚页码 |
| 并发模型 | `ThreadingHTTPServer`（HTTP/1.1 长连接）+ 后台扫描线程 + 前端轮询进度 | 扫描大仓库时前端不阻塞，可实时看到进度与当前文件 |
| 前端 | 原生 HTML/CSS/JS（无框架、无打包） | 单文件即开即用，无 node_modules、无构建产物，离线可用 |
| 报告 | 服务端渲染自包含 HTML + 标准 OOXML Word 文档 | 单文件归档，可直接归档、发送、打印为 PDF 或在 Word/WPS 中继续编辑 |

### 2.3 扫描引擎工作原理

```
文件遍历（跳过 .git/vendor/node_modules/testdata/二进制/>2MB，保留 .github）
        ↓
文本解码 + 换行归一（UTF-8 → UTF-8-BOM → GB18030 → Latin-1 逐级回退；
                   CRLF/CR 归一为 LF，保证「行号 == 行文本 == 高亮行」三者同源）
        ↓
语言识别（扩展名 + 特殊文件名，支持 Go/Java/Python/JS/PHP/Ruby/C#/C/C++/Shell/YAML/Dockerfile/Terraform/Rego）
        ↓
规则匹配（按语言过滤规则 → 单行正则匹配）
        ↓
降噪三层
   ① 同行排除（excludes）          —— 注释行、已使用安全 API 的行直接跳过
   ② 上下文守护（guard）           —— 向上 N 行若存在 len()/if err/Close() 等防护，判定为「已有校验」并抑制
   ③ 作用域降级（scope）           —— 测试/示例代码降一级；文档降为「提示」级
        ↓
风险评级（等级基准分 × 置信度系数 → 风险分 W；风险指数 = 100 × (1 − e^(−W/3000))）
        ↓
排序输出（等级 → 风险分 → 文件 → 行号）
```

风险指数采用**对数饱和**模型：单条严重问题不会把指数顶满，海量低危也不会把指数压到 0，
同时反映「严重程度」与「问题规模」两个维度。

> **行号一致性**：引擎统一用 `content.count("\n")` 计算行号、用 `content.split("\n")` 取行文本，
> 二者同源。若改用 `str.splitlines()`，它会把 `\x85`(NEL)、`\u2028`、`\x0b`、`\x0c` 也当作换行，
> 与 `count("\n")` 分叉——实测在混入 NEL 的 `application.properties` 上偏移 **4 行**，
> 导致「点开漏洞行看到无关代码」，且 `excludes` 作用在错误的行上。
> 因此读取阶段即把 CR/CRLF 归一为 LF；异形分隔符默认保留为行内字符（与 VS Code 的行模型一致），
> 只有当它们构成该文件的主要分行方式时才回落为换行。

### 2.4 规则库

共 **48 条规则**，覆盖 10 大类。规则间通过统一「优先级与冲突处理策略」协作
（详见 `core/rules.py` 头部注释）：同文件同行多规则命中时按
**severity 降序 → confidence 降序 → id 字典序** 择优保留一条；
`suppress_if`（文件级豁免）> `guard`（上下文防护）> 直接报告。

| 类别 | 代表规则 | 典型 CWE |
| :--- | :--- | :--- |
| 注入类 | SQL 拼接、命令注入、动态代码执行（`eval`/`exec`）、LDAP 注入、日志注入 | CWE-89 / 78 / 95 / 90 / 117 |
| 敏感信息泄露 | 硬编码凭据（**带引号** `SEC-KEY-001` / **未加引号的配置值** `SEC-KEY-004`）、云平台 AccessKey、API Token/私钥、URL 内嵌凭据、日志泄露 | CWE-798 / 532 |
| 越界与内存安全 | 算术索引未校验、切片边界未收敛、`unsafe` 指针运算、cgo、固定缓冲区拷贝 | CWE-125 / 787 / 823 |
| 加密与随机数 | MD5/SHA1、DES/RC4/ECB、`math/rand`、`InsecureSkipVerify`、密钥硬编码 | CWE-327 / 338 / 295 / 321 |
| 路径遍历与文件操作 | 外部输入拼路径、Zip Slip、权限 0777、可预测临时文件 | CWE-22 / 732 / 377 |

| 代码质量风险 | 忽略 error、滥用 panic、句柄未关闭、Context 无超时、HTTP 无超时、安全 TODO | CWE-391 / 248 / 404 / 400 |

每条规则包含：**规则编号、名称、风险等级、类别、适用语言、CWE、置信度、风险说明、修复建议（含可复制代码）、参考资料**。

#### 规则设计要点：`SEC-KEY-004` 如何做到「既查未加引号的凭据，又不误报」

配置文件（`.env` / `.properties` / `.yml` / `.ini`）里的凭据通常**不带引号**，
`SEC-KEY-001` 只匹配 `key = "值"` 形态，会整片漏报。`SEC-KEY-004` 用**四重守卫**补上这一盲区，
缺一不报：

| 守卫 | 作用 |
| :--- | :--- |
| ① 键名须在行首（含缩进）且命中 `password` / `secret` / `apikey` / `accesskey` / `private_key` 等敏感词 | 只在「配置项」位置判定，不误伤正文 |
| ② 值不以引号开头 | 与 `SEC-KEY-001` 分工不重叠 |
| ③ 值长度 ≥ 8 | 排除 `admin` / `root` / `123456` 之类的短值噪声 |
| ④ 值**同时**含大写、小写、数字 | 用字符多样性近似熵下界，挡住 `human_readable` 单词、类型名与纯十六进制哈希 |

配套 `excludes` 排除：变量/模板引用（`${}` / `%VAR%` / `{{}}`）、函数调用或属性链取值
（`os.getenv(...)` / `process.env.X` / `this.props.x`）、占位符（`changeme` / `your_` / `example` / `dummy`）、
掩码（`***` / `XXXXXX` / `<YOUR_KEY>`）、空值语义词（`none` / `null` / `String`）以及 `#` 注释行。

> ⚠️ **实现陷阱**：模式开头的整体 `(?i)` 会让 `[A-Z]` 这类守卫**同时变成大小写不敏感**，
> 使「字符多样性」判定彻底失效。正确做法是用局部作用域 `(?i:password|secret|...)`
> 只对键名开启不敏感匹配。该坑由 `ruletest.py` 的夹具回归捕获。

### 2.5 审计目标的选择方式（v1.2 新增）

浏览器出于安全模型**不会**把本地绝对路径交给网页（`FileSystemDirectoryHandle.name`
只给文件夹名，`webkitdirectory` 只给相对路径），因此「在网页里选目录」提供三种方式：

| 方式 | 触发 | 原理 | 适用 |
| :--- | :--- | :--- | :--- |
| **① 浏览器原生目录选择器** | 顶栏「审计目标」→「从浏览器选择」 | `window.showDirectoryPicker()` 读取目录句柄，递归收集文件后**上传到服务端工作区副本**再扫描 | 默认方式，最贴近「点一下选目录」的直觉 |
| **② 兼容模式** | 同上，当 ① 不可用（非安全上下文 / 旧内核 / 用户拒绝授权） | 自动降级到 `<input type="file" webkitdirectory>`，按 `webkitRelativePath` 上传 | 局域网 IP 访问、旧版浏览器 |
| **③ 服务器端原生对话框 / 手填路径** | 「审计目标」→「服务器目录」 | 子进程调用 Tk `filedialog.askdirectory()`，或直接填服务器上的路径 | 代码本就在服务端机器，避免上传大仓库 |

**上传协议**：一个请求一个文件（`POST /api/upload/file?ws=<id>&path=<相对路径>`，原始字节流），
可边收边落盘，无需 multipart 解析、内存峰值恒定。安全上有 `safe_join` 防路径穿越
（含 `..%2f` 编码变体）、三重限额（单文件 12MB / 单次 8000 文件 / 累计 400MB）、
二进制与压缩包双层过滤；工作区落在 `workspaces/` 下并自动只保留最近 6 份。

不管用哪种方式，切换目录后都会回填顶栏「审计目标」胶囊（目录名 + 绝对路径 + 来源标签），
并可选「仅切换」或「切换并立即扫描」。

```
工作台（#/）                每次扫描的实时结果与源码检视
   │ 顶栏「项目 ▾」→ 查看全部扫描历史
   ▼
一级：扫描历史列表（#/history）
   │  概览合计卡 · 搜索/状态筛选/排序/分页 · 记录卡（状态徽章、规模、

   │ 点击某条记录（只把项目 ID 写进 URL）

```

**跳转关系与数据传递方式**

| 环节 | 机制 | 说明 |
| :--- | :--- | :--- |
| 列表 → 详情 | **URL hash 传主键** | 点击记录只把项目 ID 写入 hash（`#/history/<pid>`），详情页拿这个 ID 自行请求 `/api/project/detail` 取全量数据。**URL 是页面层级的唯一真源**：刷新、收藏、直接粘贴链接、浏览器前进/后退全部可用，且不依赖内存中间状态 |
| 详情首屏秒开 | **sessionStorage 行概览** | 列表页点击时把已渲染的行概览写入 `sessionStorage['audit:hist:row:<pid>']`，详情页先用它立即渲染页头与骨架屏，再异步补全重区块，避免白屏；深链直达时无缓存则直接走接口渲染 |
| 详情 → 列表 | **`history.back()` / 返回按钮** | 同文档 hash 前进后退；返回时从 `sessionStorage['audit:hist:view']` 恢复搜索词、状态筛选、排序、页码，从 `audit:hist:scroll` 恢复滚动位置，回到离开时的浏览现场 |
| 详情 → 工作台 | **`在工作台中打开`** | 复用项目载入逻辑（`?project=<pid>` 参数透传），工作台进入「历史项目只读」模式；高危清单里的文件路径可一键定位到具体源码行 |
| 列表数据 | **一次请求全量** | `/api/projects` 只读小体积的 `project.json`（统计块随扫描完成回写，老项目首次访问时惰性回填一次），列表页因此**不读取任何 result.json 大文件**，记录再多也秒开 |

**状态语义**：`已完成`（静态扫描 + 依赖分析均成功）/ `部分完成`（静态扫描完整但依赖分析失败，原因随档案保留）/ `已中断`（进程中断，仅有建档信息）/ `失败`（扫描抛错，已扫到文件时保留部分快照）。

## 六、已知局限与调优建议

1. **静态分析存在误报**：本工具为模式匹配型（pattern-based）SAST，无法做完整的数据流/污点追踪。
   高误报率规则（`OOB-*`、`QUA-RES-001`）已标注低置信度，请结合人工复核确认。
2. **上下文守护是启发式**：`guard` 通过向上查找 `len()` / `defer Close()` 等关键字降噪，
   跨函数边界的防护无法识别，可能漏报。
3. **不支持跨文件跟踪**：无法追踪「A 函数接收用户输入 → 传参给 B 函数 → 在 B 中拼进 SQL」的链路。
   如需深度分析，建议叠加 CodeQL / Semgrep / gosec。
4. **SCA 的能力边界**（v1.4 起本工具已内置依赖漏洞比对，但请注意）：
   - 清单覆盖 30 种（Java/Maven+Gradle、Go、npm+Yarn、Python/pip+Poetry+Pipenv、
     Ruby、PHP、Rust、NuGet、Dart/Pub、Elixir/Hex、CocoaPods、SwiftPM），
     但语言生态远不止这些（Conda、Haskell、OCaml 等未覆盖）；
   - 版本可信度分级：`exact`（锁定文件/明确版本）可信；`floor`（`^1.2.3` 等区间下界推定）
     可能产生假阳性；`unresolved`（父 POM/BOM 管理的外部版本）不参与查询并明确提示；
   - OSV 数据有滞后：刚发布的 CVE 可能尚未收录，"暂无修复版本"不等于"永远不会修"；
   - CVSS v4 向量未实现（查表代价不划算），仅含 v4 向量的记录退回数据库文本等级并标注来源；
   - 修复建议由区间事件推导，跨主版本升级可能涉及不兼容改动，请自行评估回归成本；
   - 本工具不做可达性分析（漏洞代码是否真的被你的代码调用），
     深度需求建议叠加 `govulncheck` / `trivy fs`。
5. **docx 明细规模**：完整明细模式默认不限制条数；若仓库命中上万条，
   建议用 `detail=summary`（精简清单）或 `max=N` 限制，避免 Word 打开缓慢。
6. **调优方式**：直接编辑 `core/rules.py` 增删规则；用 `excludes` 降噪、用 `guard` 做上下文抑制、
   用 `path_exclude` 排除路径。修改后重启服务即生效。
7. **`SEC-KEY-004` 的召回边界**（有意取舍）：为避免把哈希、ID、枚举值当成凭据，
   只判定「长度 ≥ 8 且同时含大小写字母与数字」的值。后果是：
   - 纯十六进制口令哈希（`5f4dcc3b5aa765d6`）**不判定**——它本身不是可直接登录的凭据；
   - 纯小写或纯数字的长令牌（少见）会漏报；
   - 混入 `\x85` 等异形换行字符的配置文件仍可能整行过短而漏报（见下条）。
   若你的环境里这类值很常见，可放宽 `SEC-KEY-004` 的字符多样性守卫，但要接受误报上升。
8. **异形换行的取舍**：含 `\x85`(NEL) / `\u2028` 等字符的文件常是「被错误转码」的产物。
   引擎默认把它们当行内字符（与 VS Code 一致），因此行号与你在编辑器里看到的一致；
   只有当整份文件主要靠这些字符分行时，才回落为换行（此时行号与编辑器可能不同，
   但「行号 ↔ 代码片段」始终自洽，可直接照片段定位）。

## 七、目录约定

- 默认跳过：`.git`、`node_modules`、`vendor`、`dist`、`build`、`testdata`、`target`、
  `__pycache__`、`.venv`、`site-packages` 及其他点开头隐藏目录（保留 `.github`），
  以及图片/压缩包/可执行文件等二进制文件。
- 单文件扫描上限 2 MB，单次扫描文件数上限 20000。
- **上传工作区**：`workspaces/<时间戳>-<随机 id>/<你选的文件夹名>/`，
  自动只保留最近 **6** 份（超出即删最旧）。上传限额：单文件 12 MB、单次 8000 个文件、累计 400 MB；
  图片/压缩包/可执行文件等扩展名与含 NUL 字节的文件会被跳过并在界面提示。
- **报告归档**：`reports/`（可在界面导出菜单底部「查看已生成的报告」中回看与下载）。
- **漏洞库缓存**：`vulndb/cache.json`（包级 24h / 公告详情 7d 两级 TTL，超量自动淘汰；
  界面「更新漏洞库」可清空重查，`--offline` / 界面离线开关只读缓存不联网）。
- 服务默认只监听 `127.0.0.1`，不会对外暴露。若需局域网访问请显式指定 `--host 0.0.0.0`
  并自行评估网络访问控制风险。
- **可移植性相关的可编辑点**（均为纯文本，拷贝后无需重新配置）：
  - `core/meta.py` —— 工具名、**版本号**、**反馈邮箱**（`FEEDBACK_EMAIL`）、最低 Python 版本；
  - `start.bat` / `start.sh` / `checkenv.bat` —— 启动与环境自检入口；
  - `app.py` → `env_report()` —— 环境自检的检查项与判定口径。

> ⚠️ 注意：浏览器原生目录选择器（`showDirectoryPicker`）只在**安全上下文**可用
> （`http://127.0.0.1` 或 `https`）。若你以 `--host 0.0.0.0` 用局域网 IP 访问，
> 浏览器会禁用该 API，此时界面自动降级为 `<input webkitdirectory>` 兼容模式，

### 8.1 建议反馈的内容

为便于快速定位问题，请在邮件中尽量包含：

1. **工具版本号**（界面「关于与反馈」面板、报告页脚、启动控制台均可看到）；
2. **运行环境**：直接点面板里的 **「复制诊断信息」** 一键生成，内容含操作系统、
   Python 版本与解释器路径、终端编码、规则与清单数量、SCA 与联网状态、目录可写性、自检结论；
3. **问题现象**：期望结果 vs 实际结果，例如「规则 `SEC-KEY-004` 对文件 X 报了凭据，
   但该值是哈希，不应判定」；
4. **复现步骤**：从启动到出现问题的具体操作顺序（若涉及具体仓库，可只提供脱敏后的片段）；
5. **截图**（可选）：界面异常时附上截图最直观。

### 8.2 特别欢迎的反馈

- **误报 / 漏报**：某条规则在该报时没报、不该报时报了，附最小复现代码片段最佳；
- **新规则建议**：希望覆盖的语言 / 漏洞类型 / CWE，以及典型代码形态；
- **清单生态扩展**：需要支持但目前未覆盖的依赖清单格式（当前 30 种）；
- **报告口径**：Word 报告的章节结构、术语、四板块（隐患 → 整改 → 加固 → 验证）
  写法是否贴合你们的汇报规范；
- **可移植性**：在特定操作系统 / Python 版本 / 目录布局下无法启动或选目录异常，
  请附 `--check-env` 的输出。

> 控制台横幅三处均从此读取。如需改为团队统一邮箱，只需修改这一处并重启服务。
